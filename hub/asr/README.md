# neoless ASR worker

neoless-hub 的语音识别进程：在 Neo（你当处理中心的那台 Apple 芯片 Mac）上用 MLX 跑 **Qwen3-ASR**（4-bit；默认是 0.6B，也可以配一大一小两个模型，比如 1.7B 和 0.6B），只监听 `127.0.0.1:18801`，只接受带共享密钥的本机请求。接口约定见 `docs/hub.md` 的「ASR worker」一节。

模型用 mlx_audio 加载（`load_model`）和调用（`generate(language=..., hotwords=...)`）：Hub 给的热词交给模型的 `hotwords`。运行时 Hugging Face 是离线的，只用缓存里固定版本的模型，所以第一次要先把模型下载好。

中英文混着说的录音会分段识别（见下面「中英文混着说」）；只有一种语言的录音和以前一样只识别一次。

## 准备（只做一次）

`scripts/hub-deploy.sh` 会替你做第 1 步；这里是手动的做法。

1. 给 worker 一个 Python 环境（实际跑过的是 Python 3.14 和 `requirements.txt` 里写的那些版本，更旧的没试过）：

   ```bash
   python3 -m venv ~/Applications/neoless-hub/asr/.venv
   ~/Applications/neoless-hub/asr/.venv/bin/python -m pip install -r hub/asr/requirements.txt
   ```

   已经有一个装好 mlx、mlx-audio、aiohttp、numpy、scipy 的环境，也可以直接用它。
2. 下载模型（约 1.3 GB，放进 Hugging Face 的缓存；只有这一步联网）：

   ```bash
   ~/Applications/neoless-hub/asr/.venv/bin/python hub/asr/fetch_model.py
   ```

   `--check` 只看缓存里有没有，不联网。要配第二个模型（下面的 `--fallback-model`），用 `--model …` 再下载一次。

下面的命令里，`python` 都指这个环境的 Python。

## 运行

```bash
python hub/asr/asr_worker.py
```

启动后打印 `neoless-asr: ready on 127.0.0.1:18801 ...`。按 Ctrl-C 或发 SIGTERM 退出（会等正在识别的那一段做完）。

参数和环境变量（参数优先）：

- `--port` / `NEOLESS_ASR_PORT`：端口，默认 `18801`。只监听 127.0.0.1，不能改成别的地址。
- `--idle-unload` / `NEOLESS_ASR_IDLE_SECONDS`：最后一次请求结束多少秒后卸载模型，默认 `600`（10 分钟），`0` 表示一直留着。
- `--secret-file` / `NEOLESS_ASR_SECRET_FILE`：共享密钥文件，默认 `~/Library/Application Support/neoless-hub/worker-secret`。没有就创建（目录 0700、文件 0600），Hub 读同一个文件。指到别的已有文件夹时不改那个文件夹的权限；别人能写入的文件夹（/tmp 这类带粘滞位的除外）拒绝启动。
- `--model` / `NEOLESS_ASR_MODEL`：默认 `mlx-community/Qwen3-ASR-0.6B-4bit`。也可以用 `mlx-community/Qwen3-ASR-1.7B-4bit`、`mlx-community/Qwen3-ASR-1.7B-8bit`（版本都已固定，要先用 `fetch_model.py --model …` 下载好；更大，也更慢、更占内存）或一个本地模型文件夹。
- `--fallback-model` / `NEOLESS_ASR_FALLBACK_MODEL`：再配一个小模型。这时 `--model` 是“大模型”、它是“小模型”：平时用大的；大的识别一段录音的总耗时超过它该用的时间（Neo 内存紧或正忙），之后 10 分钟改用小的，再回头试大的。该用的时间 = 录音时长的 0.6 倍加 1 秒，问语言每问一个小段加 0.6 秒，每多识别一个语言段加 1 秒、再加热词每个字符 0.003 秒（见下面「时间限制」）。内存里同时只留一个。
- `--single-call` / `NEOLESS_ASR_SINGLE_CALL=1`：每段录音只调一次模型（1.3 之前的做法），不管中英文混说。出问题时用来对照。
- `--preload` / `NEOLESS_ASR_PRELOAD=1`：启动时就加载模型，而不是等第一次请求。
- `NEOLESS_ASR_KEEP_DIR`（只有环境变量，默认不设）：设了它，worker 会把收到的每段录音另存一份到这个文件夹（文件 0600；只留最新的 20 个，`NEOLESS_ASR_KEEP_MAX` 可改；超过 7 天的删掉），用来在你自己的声音上比较模型。**不设就不保存任何录音。** 用完记得去掉这个变量、删掉那个文件夹。

日志只写状态、时长和耗时，不写识别出来的文字。

## 试一下

```bash
SECRET=$(cat ~/Library/Application\ Support/neoless-hub/worker-secret)
HINTS=$(printf '["OpenAI"]' | base64 | tr '+/' '-_' | tr -d '=')
curl -s http://127.0.0.1:18801/health
curl -s -X POST http://127.0.0.1:18801/recognize \
  -H 'Content-Type: audio/wav' -H "X-Neoless-Worker: $SECRET" -H "X-Hints: $HINTS" -H 'X-Model: small' \
  --data-binary @录音.wav
```

热身（1.4 起，Hub 在设备开始听写时发，让模型趁用户还在说话就加载好）：

```bash
curl -s -X POST http://127.0.0.1:18801/warm -H "X-Neoless-Worker: $SECRET" -H 'X-Model: auto'
```

立刻回答（`{"ok": true, "model": …, "loaded": …, "warming": …}`），模型在后台加载；这期间来的识别排在它后面、不会再加载一次。模型已经在内存里时只让 10 分钟的闲置卸载重新计时。

`X-Model` 可以不带：`auto`（默认，worker 自己决定）、`large`（`--model`，哪怕它正歇着）、`small`（`--fallback-model`）。只配了一个模型时三种都是它。回答里的 `model` 是这次实际用的模型，`segments` 是分开识别了几段；`/health` 里有 `largeModel`、`smallModel`（配了才有）和 `autoUses`（`auto` 现在用 `large` 还是 `small`）。

录音要求单声道 16 位整数 PCM WAV，最好是 16 kHz（`afconvert -f WAVE -d LEI16@16000 -c 1 输入 输出.wav`）；浮点、A-law/μ-law 等其他格式回 415。AVAudioFile 写的文件要等它释放后再读：写入器还在时文件头里 data 长度是 0，worker 能认出来、照样读后面的采样，但日志会提一句。8–48 kHz 也行，会先用 scipy 的多相滤波转成 16 kHz：耗时只跟长度有关，10 分钟 48 kHz 约 0.3 秒、约 80 MB；第一次遇到非 16 kHz 的录音还要多花 1–2 秒载入 scipy。重采样在推理线程上逐个请求做（同一时间只占一份内存），不算进 `asrMs`。

热词（`X-Hints`）最多 100 个、每个最多 80 字符，整个列表按紧凑 JSON 不超过 2000 字符：每次调用模型（每 30 秒一块、每个语言段）都把全部热词放进提示词，列表越长每次越慢。实测一次调用：1.7B 带 30 个热词（约 400 字符）多 0.6–0.9 秒，带 100 个（约 1500 字符）多 3 秒左右；0.6B 分别是 0.3 秒和 1.2 秒。

## 中英文混着说

Qwen3-ASR 一次调用只给整段录音写一个语言标签。一段录音里中文句子和英文句子都有时：1.7B 把整段答成英文，中文句子被翻译成英文或者直接漏掉；0.6B 好一些，但会丢句子（长录音里尤其）。强制指定中文也不行：开头的英文句子会被跳过；强制英文则把中文翻译掉。

现在的做法（`asr_worker.py` 的 `transcribe_mixed`，纯函数加两个模型调用）：

1. **在停顿处切开**：每个 ≥ 0.2 秒的停顿中间切一刀（阈值按这段录音自己的音量定，有底噪也行，除非和说话声差不多大；不丢任何采样）。只有一段，或总共说话不到 2 秒：和以前一样只调一次，到此为止。
2. **问每一小段是什么语言**：把小段开头 2 秒（两头垫一点静音）交给模型，只生成 10 个 token（语言标签和头几个字），不带热词，最多 12 段并排解码。先问说话满 1 秒的小段；它们有两种语言时才再问更短的。标签是中文就是中文；标签是英文但头几个字有汉字，也是中文（1.7B 常把夹着英文词的中文句子标成英文）；标签是英文而且有四个以上英文词（或者两三个词、话还没说完）才算英文开头——三个词以内就说完的（“OK”“Thank you”、停顿之间单说的术语 “Hidden Markov Model”）不算；别的都不算数。
3. **英文开头的小段，再问结尾**：把它最后 1 秒也交给模型。英文后面不停顿接着说中文（“As far as I know 他明天不来”）时，开头听起来是英文，整段按英文识别，1.7B 就把后面的中文翻译掉；结尾单听是中文（标签是中文，或有汉字），这一段就算中文——指定中文时两个模型都照原话写，前面的英文也在。结尾标签是英文才算英文，听不出来就不算数。
4. **合成语言段**：相邻同语言的小段合在一起。不到 1 秒或语言不算数的小段不单独成段，并到同语言的邻居，没有就并到停顿更短的那边。一种语言连着超过 29.5 秒，在停顿处再分开（加上两头垫的 0.5 秒静音正好 30 秒）。说话满 1 秒的小段超过 36 个的长录音（大约两分钟以上）只问第一段和最长的 35 个停顿后面的那些，其余的跟着它们走：问一段的时间不随长度变，全问的话十分钟的录音光问语言就要一分多钟。
5. **每段识别一次**，带着自己的语言和全部热词；文字拼起来：中文挨中文、全角标点两边不加空格，其余加一个空格。只有一个语言段时整段录音原样识别一次（和以前的区别只是语言已经定了）。

超过 30 秒的音频由 worker 自己分块（`chunk_bounds`），不交给 mlx_audio：切法和它一样（每 30 秒前后 5 秒内最安静的 0.1 秒），但后面没人说话的地方不切，整块没人说话的不送给模型。mlx_audio 找“最安静”常常找到结尾（垫的静音一定是），最后一块就成了 0.1 秒静音；语言一旦指定，两个模型都会给静音写字：1 秒静音、指定中文，不带热词写“嗯。”，带 10 个热词时 1.7B 写出其中一个词、0.6B 把整个热词表写出来（不指定语言时什么都不写）。

做不到的：

- 换语言时完全没有停顿（见下面实测里的“两个人声、没有停顿”）：切不开，和以前一样看模型。同一个人一句话里夹英文词（“这个 feature 应该在下个 sprint 之前 ship 出去”）本来就没问题。开头和结尾都是英文、中间夹一段中文的小段算英文。
- 不到 1 秒的另一种语言的话（英文句子后面的一声“谢谢”）：跟着旁边那句的语言走，1.7B 会漏掉它，0.6B 一般能留住。
- 一句中文里停顿之间单说的四个词以上的英文（“…以前说过｜move fast and break things｜这句话…”，前后都有停顿）：会单独成段，这句话被写成三句，各带一个句号（按规则是这样，没有单独测）。三个词以内的术语、和后面的中文连着说的英文都没有这个问题（测过）。
- 底噪和说话声差不多大时一个停顿也找不到（每一帧都算说话），整段录音按一次调用识别，和 1.3 之前一样。用白噪声试过：比说话声低 17 dB 还切得开，低 12 dB 就切不开了；真实的房间噪声没试过。
- 代价是时间：有停顿的录音多一轮“问语言”（有英文的再问一轮结尾），每换一次语言多一次模型调用、多读一遍热词。实测大约是原来的两到三倍；没有停顿的录音不变。嫌慢可以让设备选小模型（`X-Model: small`，同样的做法、快得多），或者用 `--single-call` 关掉。

### 时间限制

有停顿的录音比一次调用慢，所以三处按“一次调用”定的时间限制一起改了：

- worker 判断“大模型太慢、换小模型十分钟”（`AdaptiveEngine.slow_limit`）：录音时长 × 0.6 + 1 秒是一次调用的份，和以前一样；问语言每个小段加 0.6 秒；每多一个语言段加 1 秒，再加热词每字符 0.003 秒。`compare.py` 每行的 `slowLimit` 就是这个数。
- Hub 在设备自己也听出了文字时等 worker 的时间（`ASRWorker.impatientTimeout`）：当时改成 6 + 0.8 × 时长、最多 60 秒（原来是 0.5）。后来又缩短了，现在是 2.5 + 0.4 × 时长、最多 20 秒（`HubTimeouts.standInRecognition`）；热身之后 20 秒内、模型可能还在加载时再多等 3 秒（`HubTimeouts.standInLoad`）。过了就用设备的文字整理。
- 设备给识别留的时间：8 秒加每秒录音 0.8 秒（`HubTimeouts.modelLoad`、`asrPerAudioSecond`；每秒原来是 0.3），比 Hub 的两种等法（旧的 6 + 0.8 × 时长，现在的 2.5 + 0.4 × 时长再加 3 秒）都长，有意如此：Hub 改用设备文字时的回答总落在设备的预算之内。这几个数的来历见 [docs/hub.md](../../docs/hub.md) 的「`POST /v1/dictations`」一节。

### 试过的做法

用 `say`（婷婷、Samantha）合成的录音，在一台 8 GB 内存的 Apple 芯片 Mac 上比过（2026-10-11，每种做法、两个模型）：

- **一次调用、自动语言**（原来的做法）：1.7B 遇到中英句子交替，全部答成英文（中文句子被翻译或漏掉）；0.6B 大多能对，但 60 秒的录音丢了一句英文和一个字，两个人声没有停顿时丢了英文那半句。
- **强制语言**：强制中文，两个模型都会跳过开头的英文句子；强制英文，1.7B 把中文翻译成英文（“Codex 帮我把这个 bug 修好了”→“Codex, help me fix this bug.”），0.6B 有一段写成了繁体。
- **每个停顿小段单独识别再拼起来**：语言都对，但小段没有上下文：一个缩写被停顿切成两半（各带一个句号），每个逗号处都变成句号，1.7B 把一个英文词听成了同音的另一个词，夹在英文旁边的“谢谢”被漏掉；耗时是一次调用的 1.4–2 倍。
- **先问每个小段的语言，再按语言段识别**（现在的做法）：语言都对，一种语言的录音和原来逐字相同。
- **只凭小段开头定语言**（1.3 的第一版，2026-10-12 复查时改掉）：“As far as I know 他明天不来”这种英文开头、不停顿接中文的小段，1.7B 问开头时答 “As far as I know, he”，整段被指定成英文，中文就被翻译了（“he's not coming.”，“明天”丢了；一次调用反而是对的）。所以英文开头的小段要再问结尾。同一轮里，停顿之间单说的三个词的术语（“用的是｜Hidden Markov Model｜来做…”）原来算英文句子，一句话被写成三句；现在三个词以内就说完的不算。
- **让 mlx_audio 自己分 30 秒的块**（同上）：29.5–30 秒的语言段垫上静音后是 30–30.5 秒，mlx_audio 在垫的静音里切一刀，最后一块是 0.15 秒静音，模型给它写字——1.7B 在两句之间多写一个“例会。”，0.6B 把整个热词表写进正文。现在 worker 自己切，后面没人说话的地方不切。
- mlx_audio 里别的办法：`system_prompt` 里写“中英混说，每句用原来的语言写，不要翻译”（中文写、英文写、只写“中文 English 中英文混合”）没有用：1.7B 对“中 英 中 英”照样全篇英文，对“英文一句 → 中文一句”三种写法里一种碰巧对了、一种把中文句子直接漏了；一次传多段音频只是逐段调用；它把长录音的 30 秒分块并排解码的那段代码（`_generate_chunks_batched`，不是公开接口）被用来并排问语言，出任何意外就退回每段一次公开调用（结果一样，慢一倍左右）。

### 实测

`compare.py --say`（见「测试」）的 17 段录音，在 Neo 上的结果（2026-10-12，复查修改之后；每种做法测了三次、分两轮，秒数取最快的一次）。Neo 当时同时在忙别的（负载 6–20，一直在用交换区），第二轮末尾负载过百，同样的录音慢了 2 倍以上，所以这些是“Neo 大致跟得上”时的数。括号里：分开识别了几段、一共问了几个小段（开头和结尾都算）；“太慢”线是 worker 认为大模型跟不上的秒数（`slowLimit`）。公开时 `compare.py` 里“带术语的中文”那句的缩写和那 10 个热词里的几个换成了别的词；下面的数字和文字是换之前测的，换了以后没有重测。

- 英文一句 → 中文一句（5.7 秒）：1.7B 一次调用 0.9 秒 → 现在 2.4 秒（“太慢”线 7.2 秒）；0.6B 0.4 秒 → 1.2 秒（2 段，问 3 个小段）
- 中文一句 → 英文一句（6.3 秒）：1.7B 一次调用 1.1 秒 → 现在 2.7 秒（“太慢”线 7.6 秒）；0.6B 0.4 秒 → 1.2 秒（2 段，问 3 个小段）
- 中 英 中 英（三次切换，停顿 0.45 秒）（12.6 秒）：1.7B 一次调用 1.8 秒 → 现在 5.2 秒（“太慢”线 15.2 秒）；0.6B 0.8 秒 → 2.4 秒（4 段，问 6 个小段）
- 中 英 中 英（停顿只有 0.25 秒）（12.0 秒）：1.7B 一次调用 1.8 秒 → 现在 5.0 秒（“太慢”线 14.8 秒）；0.6B 0.9 秒 → 2.4 秒（4 段，问 6 个小段）
- 带术语的中文（Codex、OpenAI 和一个缩写，带热词）（9.5 秒）：1.7B 一次调用 1.4 秒 → 现在 3.1 秒（“太慢”线 8.5 秒）；0.6B 0.6 秒 → 1.4 秒（问 3 个小段）
- 纯英文一段（13.9 秒）：1.7B 一次调用 2.8 秒 → 现在 5.7 秒（“太慢”线 14.8 秒）；0.6B 1.0 秒 → 2.7 秒（问 9 个小段）
- 纯中文一段（14.5 秒）：1.7B 一次调用 2.1 秒 → 现在 4.2 秒（“太慢”线 12.7 秒）；0.6B 1.1 秒 → 2.0 秒（问 5 个小段）
- 一句话里夹英文词、没有停顿（6.7 秒）：1.7B 一次调用 1.7 秒 → 现在 1.7 秒（“太慢”线 5.0 秒）；0.6B 0.7 秒 → 0.7 秒（不问语言）
- 两个人声、没有停顿（英文半句接中文半句）（4.5 秒）：1.7B 一次调用 1.2 秒 → 现在 1.2 秒（“太慢”线 3.7 秒）；0.6B 0.3 秒 → 0.3 秒（不问语言）
- 英文一句，然后一声“谢谢”（3.4 秒）：1.7B 一次调用 0.7 秒 → 现在 2.4 秒（“太慢”线 4.9 秒）；0.6B 0.4 秒 → 1.0 秒（问 3 个小段）
- 60 秒，中英各几段（63.0 秒）：1.7B 一次调用 9.7 秒 → 现在 27.5 秒（“太慢”线 62.2 秒）；0.6B 5.0 秒 → 9.5 秒（7 段，问 29 个小段）
- 英文开头不停顿接中文，三句，前后各一句中文（15.3 秒）：1.7B 一次调用 3.4 秒 → 现在 7.5 秒（“太慢”线 14.4 秒）；0.6B 1.0 秒 → 1.9 秒（问 7 个小段；0.6B 1 段、问 5 个）
- 英文开头接中文两句，再一句中文（11.7 秒）：1.7B 一次调用 2.7 秒 → 现在 4.6 秒（“太慢”线 11.0 秒）；0.6B 0.9 秒 → 1.3 秒（问 5 个小段；0.6B 1 段、问 3 个）
- 停顿之间单说一个术语（Hidden Markov Model）（6.2 秒）：1.7B 一次调用 1.4 秒 → 现在 2.8 秒（“太慢”线 6.5 秒）；0.6B 0.4 秒 → 1.0 秒（问 3 个小段）
- 停顿之后一句英文引语接着说中文（9.5 秒）：1.7B 一次调用 1.8 秒 → 现在 4.0 秒（“太慢”线 9.1 秒）；0.6B 0.6 秒 → 1.4 秒（问 4 个小段）
- 同一个声音，中文 英文 中文各一句（8.2 秒）：1.7B 一次调用 1.6 秒 → 现在 4.7 秒（“太慢”线 10.3 秒）；0.6B 0.5 秒 → 1.5 秒（3 段，问 4 个小段）
- 73 秒纯中文，带一点底噪和 10 个热词（73.2 秒）：1.7B 一次调用 11.8 秒 → 现在 23.6 秒（“太慢”线 61.8 秒）；0.6B 4.4 秒 → 9.0 秒（3 段，问 24 个小段）

所以：没有停顿的录音不变；有停顿的录音是一次调用的两到三倍时间（上面 1.4–3.4 倍，短录音和换语言次数多的更高）。按录音时长算，大模型每秒录音 0.3–0.5 秒（几秒的短录音更高；一次调用是 0.15–0.25 秒），小模型 0.1–0.2 秒。多出来的主要是问语言：每问一个小段，1.7B 约 0.3–0.5 秒、0.6B 约 0.2 秒，生成几个 token、窗口多长都差不多（时间花在每个窗口各自的提示词和音频编码上）；其次是每多一个语言段多一次调用（提示词里再读一遍热词）。大模型的耗时是“太慢”线的 0.3–0.5 倍。

文字（两个模型、两种做法的完整输出见 `compare.py` 的 JSON）：

- 英文一句 → 中文一句：一次调用 1.7B 把中文句子翻译成英文（“Remember, before lunch, send the report to me.”）；0.6B 对。现在：两个模型都对，“I think the new build is ready for testing. 记得午饭之前把报告发给我。”
- 中文一句 → 英文一句：一次调用 1.7B 漏掉中文句子，只剩英文那句；0.6B 对。现在：两个模型都对
- 中 英 中 英（三次切换，停顿 0.45 秒）：一次调用 1.7B 漏掉第一句中文、把第二句翻译成英文，全篇英文；0.6B 语言都对（英文句子用了全角句号）。现在：两个模型都是“我们把每周的例会改到星期四下午吧。Please send me the report before lunch. 这个周末的天气应该会很不错。The battery on my laptop only lasts three hours.”
- 中 英 中 英（停顿只有 0.25 秒）：一次调用 1.7B 同上，全篇英文；0.6B 语言都对。现在：两个模型都对
- 带术语的中文（Codex、OpenAI 和一个缩写，带热词）：一次调用 1.7B 对；0.6B 对。现在：和一次调用逐字相同（只识别一次）
- 纯英文一段：一次调用 1.7B 对；0.6B 对。现在：逐字相同
- 纯中文一段：一次调用 1.7B 对；0.6B 对。现在：逐字相同
- 一句话里夹英文词、没有停顿：一次调用 1.7B 对（“我觉得这个 feature 应该在下个 sprint 之前 ship 出去，不然 deadline 就来不及了。”）；0.6B 对。现在：不问语言，逐字相同
- 两个人声、没有停顿（英文半句接中文半句）：一次调用 1.7B 只剩英文半句；0.6B 只剩中文半句。现在：一样（没有停顿，切不开）
- 英文一句，然后一声“谢谢”：一次调用 1.7B 漏掉“谢谢”；0.6B 对。现在：一样：1.7B 还是漏掉“谢谢”，0.6B 对
- 60 秒，中英各几段：一次调用 1.7B 漏掉开头整段中文、最后一句中文翻译成英文；0.6B 丢了一句英文（The battery…）和“楼下”的“楼”。现在：两个模型都一句不少，各是各的语言（7 段）
- 英文开头不停顿接中文（“To be honest with you 我不太喜欢｜As far as I know 他明天不来｜Long story short 我们赢了”，前后各一句中文）：一次调用 1.7B 漏掉第一句中文，其余是对的；0.6B 对。复查之前：1.7B 写成 “As far as I know, he's not coming. Long story short, we won.”。现在：两个模型都是“…As far as I know，他明天不来。Long story short，我们赢了。…”，五句都在（整段按中文识别一次）。婷婷把 “you” 念得像“有”，两个模型、两种做法都写成了“To be honest with，有我不太喜欢”或“…with you，有我不太喜欢”
- 英文开头接中文两句，再一句中文：一次调用 1.7B 全篇翻译成英文（“…I think the old version is better. …this feature will be launched next week. …”）；0.6B 对。现在：两个模型都照原话写（1.7B：“As far as I know，这个功能下周才会上线。”），三句都在
- 停顿之间单说一个术语：一次调用两个模型都是“我们这个项目用的是 Hidden Markov Model 来做语音识别的后处理。”。复查之前：两个模型都写成三句，“我们这个项目用的是。Hidden Markov model. 来做语音识别的后处理。”。现在：和一次调用逐字相同
- 停顿之后一句英文引语接着说中文：一次调用 1.7B 把“扎克伯格”写成 “Zuckerberg”，其余对；0.6B 对。复查之前：“扎克伯格以前说过。Move fast and break things.这句话…”（0.6B 还多出一对空引号）。现在：1.7B “扎克伯格以前说过“move fast and break things”这句话，现在看其实是有问题的。我们还是应该稳一点。”，0.6B 和它的一次调用逐字相同
- 同一个声音，中文 英文 中文各一句：一次调用 1.7B 全篇翻译成英文（“I asked the boss. …So this matter will be put aside.”）；0.6B 对（英文句子放进了引号）。现在：1.7B “我昨天问了一下老板。He said we should wait until next week. 所以这个事情先放一放。”，0.6B 同样三句，英文那句写成 He said, "We should wait until next week."（各 3 段）
- 73 秒纯中文，带一点底噪和 10 个热词：一次调用两个模型都对。复查之前，第一段正好落在 29.5–30 秒的类似录音里，1.7B 在两句之间多写一个“例会。”，0.6B 把十个热词全写了进去。现在：两个模型都对，没有多出来的字（3 段）

## 测试

单元测试用假的识别引擎，不加载模型，十来秒跑完（切段、问语言、拼接、30 秒分块、按请求选模型、整段计时判断快慢都在这里；有一个测试用 mlx_audio 自己的切分函数核对分块，不加载模型，环境里没有 mlx_audio 时跳过）：

```bash
cd hub/asr && python -m unittest -v test_asr_worker
```

真实模型的冒烟测试（会加载模型，占几百 MB 内存；内存小的 Mac 上别和编译同时跑）：在空闲端口启动一个临时 worker（用临时密钥文件，不碰正式的），把 WAV 发两次（第一次含加载模型）、带热词再发一次，打印结果后停掉 worker。加 `--idle-unload 5` 还会等模型卸载、再发一次确认能重新加载。

```bash
say -v Tingting "明天下午三点开会，讨论一下 OpenAI 的订阅费用" -o /tmp/neoless-asr-smoke.aiff
afconvert -f WAVE -d LEI16@16000 -c 1 /tmp/neoless-asr-smoke.aiff /tmp/neoless-asr-smoke.wav
python hub/asr/smoke.py /tmp/neoless-asr-smoke.wav --hints OpenAI --port 18851
```

两个模型和 `X-Model`：加 `--model mlx-community/Qwen3-ASR-1.7B-4bit --fallback-model mlx-community/Qwen3-ASR-0.6B-4bit --ask auto large small`，每个文件再按三种选择各发一次，并打印 `/health`。

中英混说的对比（不启动 worker，直接加载模型，一次一个；内存小的 Mac 上别和编译同时跑）：`--say 文件夹` 用 `say` 现做一批测试录音（英中、中英、三次切换、带术语的中文、纯英文、纯中文、没有停顿的一句、60 秒；英文开头接中文、停顿之间的术语和引语、同一个声音的英文句子、带一点底噪的 73 秒中文），每段分别用“一次调用”和现在的做法识别，打印文字、段数、问了几个小段、秒数和 `slowLimit`（worker 认为大模型“太慢”的秒数）。`--only 名字…` 只做其中几段；也可以直接给 WAV 文件。

```bash
python hub/asr/compare.py --say /tmp/neoless-asr-mix --models large small
```

实测（2026-10-09，一台 8 GB 内存的 Apple 芯片笔记本，`say -v Tingting` 合成的 4.8 秒中文，16 kHz）：识别为「明天下午三点开会，讨论一下OpenAI的订阅费用。」；第一次请求加载模型约 1.8–2.5 秒，卸载后再加载约 0.6 秒；模型已加载时识别约 0.33–0.5 秒。同一段先转成 48 kHz（或 44.1 kHz）再交给 worker 时，不带热词识别成「Open爱」，带热词 `OpenAI` 就对了——换 FFT、scipy 或 afconvert 重采样都一样，是这段声音本身在模型上的临界结果，不是重采样的问题。

## 部署

`scripts/hub-deploy.sh` 把 worker 装成一个 LaunchAgent（`<前缀>-asr`，前缀见 `hub/hub.env.example`）：`ProgramArguments` 是上面那个 Python 加 `asr_worker.py` 的绝对路径，`KeepAlive`、`RunAtLoad`，`EnvironmentVariables` 里设 `PYTHONUNBUFFERED=1` 和 Hugging Face 的离线开关；`local/hub.env` 里写了 `NEOLESS_ASR_MODEL`、`NEOLESS_ASR_FALLBACK_MODEL`、`NEOLESS_ASR_KEEP_DIR` 的，也放进去。日志在 `~/Applications/neoless-hub/logs/asr.log`。
